# AgentNine audit 001

Read-only codebase and live-site review. No application source files were changed.

## Findings

### 1. HIGH: Production visitor preferences return 503

The live site logged failures for `/api/preferences`. The browser showed no consent banner; theme switching worked for the current visit but the preference could not be saved. This also prevents analytics consent, theme, comparison, recent-agent, and setup-progress preferences from being reliably loaded or stored.

The client resets to a not-ready snapshot after a failed preference request, while the consent banner renders only when the snapshot is ready. The API checks shared rate limiting before querying Supabase, so the browser evidence does not isolate the failing dependency. Check Vercel function logs for the first failure in the rate-limit service, Supabase admin configuration, or the preference query/RPC.

Relevant code: [`lib/visitor-preferences.ts`](../lib/visitor-preferences.ts), [`components/ConsentBanner.tsx`](../components/ConsentBanner.tsx), and [`app/api/preferences/route.ts`](../app/api/preferences/route.ts).

### 2. HIGH: Pending Vercel Analytics change bypasses the site's opt-in promise

The local-only change mounts `<Analytics />` globally in `app/layout.tsx`. The installed Vercel Analytics Next.js component injects its tracker and emits route pageviews when mounted; this use has no consent gate. The site's Cookies page says optional analytics is off until the visitor allows it. Keep this change out of production until analytics tracking is gated on explicit consent and remains off when preferences cannot be loaded.

This change is not present in the current GitHub `main` or the live site.

Relevant code: [`app/layout.tsx`](../app/layout.tsx), [`app/cookies/page.tsx`](../app/cookies/page.tsx), and [`components/ConsentBanner.tsx`](../components/ConsentBanner.tsx).

### 3. MEDIUM: Hero heading overlaps the horizontal preview at short viewport heights

At a live viewport of 788 by 471 CSS pixels, the hero heading occupied y=152..287 while the preview strip began at y=220, overlapping by 67 pixels. At 1280 by 900 and 390 by 844, those elements did not overlap. This is a short/narrow viewport layout defect even though the document itself had no horizontal overflow.

Relevant code: [`app/globals.css`](../app/globals.css), `.fey-hero-title` and `.fey-deck-scroll`.

### 4. LOW: Standard test and lint commands are missing

`npm test` and `npm run lint` both fail with “Missing script”. The underlying tools work when invoked directly: `npx vitest run` and `npx eslint .` passed. GitHub reports no Actions workflows registered on `main`, so there is currently no hosted workflow running those checks.

Relevant code: [`package.json`](../package.json).

### 5. LOW: Design direction and liveliness dials are not documented

No `DESIGN.md` was found. The live interface has recognizable brand choices, but its design rationale and ENERGY/RHYTHM/MOTION dials are not recorded in the repository, making future visual changes harder to keep consistent.

- The page had no document-level horizontal overflow at the tested 390-pixel viewport. The card preview is a focusable horizontal scroll region.
- The visitor-preferences 503 remained the main functional production error observed.
